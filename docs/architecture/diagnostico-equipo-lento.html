Diagnóstico en un equipo de menor desempeño

SteelheadAutomator · versión 1.11.109 · 7 de agosto de 2026

Los arreglos del 7 de agosto se midieron en una Mac. Falta comprobarlos en uno de los equipos Windows donde se reportó la falla — eso es lo único que convierte «debería funcionar» en «funciona». Esta comprobación toma menos de dos minutos y no modifica nada: solo lee.

Antes de empezar: recarga la página con Ctrl+Shift+R. Una pestaña que ya estaba abierta sigue usando el código viejo, y entonces la prueba mide la versión equivocada.

Los pasos

1
En el equipo lento, entra a Steelhead y ve a Recepción → Recibir piezas del cliente, con el modal abierto.
2
Abre la consola: F12 (o Ctrl+Shift+J) y entra a la pestaña Console.
3
Copia el bloque de abajo, pégalo en la consola y presiona Enter. Si Chrome pide escribir allow pasting, escríbelo y vuelve a pegar.
4
Copia el resultado y mándalo. Con eso se cierra la comprobación.
(() => {
  const v = (window.REMOTE_CONFIG || {}).version || '(no cargó el config)';
  const q = s => !!document.querySelector(s);
  const r = {
    version: v,
    pantalla: location.pathname,
    'campo FECHA (receiver-date-override)': q('[data-sa-rdo-field="true"]'),
    'campo UBICACIÓN (warehouse-location-prefill)': q('[data-sa-wlp-field="true"]'),
    'modal detectado por WLP': q('[data-sa-wlp-attached="true"]'),
    'peso rápido (weight-quick-entry)': q('[data-sa-wqe-attached]'),
    'applets cargados': ['ReceiverDateOverride','WarehouseLocationPrefill','CreateOrderAutofill',
                         'ProcesosCalculator','UnitAutoConvert']
      .filter(n => window[n]).join(', ') || 'NINGUNO',
    'nucleo de anclaje': !!(window.ReceiveModalAnchorCore || {}).firstMounted,
    'memoria JS (MB)': performance.memory
      ? Math.round(performance.memory.usedJSHeapSize / 1048576) : 'n/d',
    'nucleos de CPU': navigator.hardwareConcurrency || 'n/d'
  };
  console.table(r);
  return JSON.stringify(r, null, 1);
})()

Cómo se lee el resultado

RenglónQué significa
version Debe decir 1.11.109 o más. Si dice menos, la extensión no se actualizó y la prueba no vale: vuelve a recargar.
campo FECHA y campo UBICACIÓN Los dos en true = el arreglo funciona. Es la respuesta que buscamos.
Alguno en false Sigue fallando. Manda el resultado completo y lo que salga en rojo o amarillo en la consola: ahí está el motivo.
modal detectado por WLP en true pero campo UBICACIÓN en false Caso concreto y útil: el applet ve el modal pero no logra colgar su campo. Es distinto de «no se enteró», y lleva a otro arreglo.
nucleos de CPU y memoria JS Para saber con qué equipo estamos comparando. No hay que hacer nada con esto.
Si todo sale true a la primera: vale la pena repetirlo una segunda vez navegando por el menú (sin recargar) y abriendo el modal de nuevo. Ese camino —entrar, salir y volver— es justo el que fallaba antes, y es el que más conviene confirmar.
